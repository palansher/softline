### __consumer_offsets - что это ?

**`__consumer_offsets`** — это главный внутренний (системный) топик Apache Kafka. В нём Kafka хранит **текущий прогресс (оффсеты) всех групп консьюмеров** в кластере.

Если упростить: это «база данных» самой Кафки, где записано, кто, из какого топика и до какого сообщения всё вычитал.

---

#### Как это работает внутри?

Когда ваш `consumer.py` или любая другая группа отправляет коммит (автоматически или вручную), Kafka пишет в топик `__consumer_offsets` обычное сообщение:

- **Ключ (Key):** Кортеж вида `[Group ID, Topic Name, Partition]`
*(например: `['person_group', 'topic2', 0]`)*
- **Значение (Value):** Номер оффсета + timestamp + метаданные
*(например: `offset: 29`)*

Когда консьюмер перезапускается или происходит ребалансировка, он обращается к этому топику, находит последнюю запись по своей группе и понимает, с какого места продолжать чтение.

---

#### Почему у него аж 50 партиций?

По умолчанию в Kafka параметр `offsets.topic.num.partitions = 50`.

Это сделано для **масштабируемости и высокой производительности**:

1. В продакшене у вас могут быть сотни топиков и тысячи консьюмер-групп, постоянно пишущих коммиты.
2. Чтобы коммиты оффсетов не стали бутылочным горлышком, нагрузка размазывается по 50 партициям между всеми брокерами кластера.

##### Связь с Group Coordinator

Kafka определяет партицию для группы по формуле:
`abs(hash(group_id)) % 50`

Брокер, который является **лидером** этой конкретной партиции в `__consumer_offsets`, становится **Group Coordinator** (Координатором группы) для вашей консьюмер-группы.

*(Именно его логику вы видели чуть раньше в терминале, когда консьюмер искал coordinator-1 на порту 9091).*

---

#### Важные детали с ваших скриншотов

1. **`cleanup.policy: compact`**
Для этого топика включена **Log Compaction** (компакция логов). Нам не нужна вся история того, как оффсет рос с 0 до 1000. Нам важен только **самый свежий** оффсет для каждого ключа. Фоновый процесс Kafka регулярно удаляет дубликаты ключей, оставляя только актуальные значения.
2. **Префикс `__**`
Двойное подчеркивание — стандартное соглашение Kafka для системных топиков. Помимо `__consumer_offsets`, вы можете встретить, например, `__transaction_state` (для транзакций).
