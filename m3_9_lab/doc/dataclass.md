Мы используем данный декоратор, когда мы хотим более компактно описать структуру нашего класса.

Явно конструктор не пишем. Он создан будет по умолчанию с помощью этого декоратора.

будет автоматически создан как конструктор, так и некоторые другие магические методы.

С помощью этого решения мы можем передавать в Kafka объекты, любые, людей, автомобили и прочее.

Оба этих параметра используются для **оптимизации памяти, повышения скорости и защиты данных** вашего класса. Они превращают стандартный датакласс в максимально строгую и быструю структуру данных.

```python
@dataclass(slots=True, frozen=True)
class CarBrand:
    id: int
    name: str

    def to_dict(self) -> dict[str, Any]:
        """Преобразует объект в словарь."""
        return asdict(self)

```

## аргументы slots=True, frozen=True

### 1. `frozen=True` — Неизменяемость (Immutability)

По умолчанию поля датакласса можно менять в любой момент. Флаг `frozen=True` делает объект **«замороженным» (read-only)** после создания.

#### Что происходит при `frozen=True`

- **Запрет редактирования:** Любая попытка изменить значение поля или добавить новое вызовет ошибку `FrozenInstanceError`.

```python
car = Car(id=1, model="Camry", ...)
car.model = "RAV4"  # Ошибка: dataclasses.FrozenInstanceError!

```

- **Автоматический хэш (`__hash__`):** Так как объект гарантированно не меняется, Python автоматически генерирует для него метод `__hash__()`.
- **Возможность использовать в `dict` и `set`:** Только `frozen`-объекты можно использовать в качестве ключей словарей или добавлять во множества:

```python
cars_set = {car1, car2}  # Сработает только при frozen=True
car_owners = {car1: "Иван"}

```

> **Важная деталь:** Неизменяемость здесь «поверхностная» (shallow). Если внутри `frozen`-датакласса лежит обычный список `list`, добавить элемент в этот список вы сможете, но переприсвоить само поле — нет.

---

### 2. `slots=True` — Экономия памяти и скорость

Добавлен в Python 3.10. Он автоматически генерирует внутреннюю инструкцию `__slots__` для класса.

#### Что происходит при `slots=True`

- **Отмена `__dict__` (Экономия RAM):** По умолчанию каждый объект в Python хранит свои атрибуты в специальном словаре `__dict__`. Это гибко, но потребляет много оперативной памяти. `slots=True` удаляет этот словарь и выделяет под атрибуты жестко фиксированные ячейки.
- *Результат:* Экономия от **30% до 60% памяти** на каждом экземпляре класса. Это суперкритично, если вы выкачиваете и обрабатываете сотни тысяч сообщений из Kafka одновременно.

- **Ускорение доступа:** Обращение к полям (`car.model`) происходит слегка быстрее, так как Python ищет их по фиксированному индексу в памяти, а не ищет ключ в словаре.
- **Запрет произвольных полей:** Нельзя на лету приписать объекту новое поле, которое не было объявлено в датаклассе:

```python
car.custom_field = "test"  # Ошибка: AttributeError!

```

---

### Сравнение режимов

| Режим | Можно менять поля? | Память на объект | Можно добавить случайное поле? | Можно в `set` / `dict` key? |
| --- | --- | --- | --- | --- |
| `@dataclass` (по умолчанию) | Да | Высокая | Да | Нет |
| `@dataclass(frozen=True)` | Нет | Высокая | Нет | **Да** |
| `@dataclass(slots=True)` | Да | **Низкая** | Нет | Нет |
| `@dataclass(slots=True, frozen=True)` | **Нет** | **Низкая** | **Нет** | **Да** |

#### Итог

Комбинация `(slots=True, frozen=True)` — золотой стандарт для **DTO (Data Transfer Objects)**, моделей событий Kafka/RabbitMQ и любых сущностей, которые служат только для передачи и чтения данных.

## наследование датаклассов в Python

При наследовании датаклассов в Python действует **строгое правило однородности**: все классы в цепочке наследования должны иметь **одинаковый параметр `frozen**`. Смешивать «замороженные» и «обычные» датаклассы нельзя.

---

### 1. Главное правило: `frozen` нельзя смешивать

Python выбросит ошибку `TypeError`, если у родительского и дочернего классов будут разные настройки `frozen`:

#### ❌ Нельзя отнаследовать обычный датакласс от `frozen`

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Parent:
    id: int

@dataclass  # по умолчанию frozen=False
class Child(Parent):
    name: str

# TypeError: cannot inherit non-frozen dataclass from a frozen dataclass

```

#### ❌ Нельзя отнаследовать `frozen` датакласс от обычного

```python
@dataclass  # frozen=False
class Parent:
    id: int

@dataclass(frozen=True)
class Child(Parent):
    name: str

# TypeError: cannot inherit frozen dataclass from a non-frozen dataclass

```

---

### 2. Как правильно наследовать `frozen`-датаклассы

Флаг `frozen=True` (как и `slots=True`) нужно явно указывать **на каждом уровне** наследования:

```python
from dataclasses import dataclass

@dataclass(slots=True, frozen=True)
class BaseEntity:
    id: int

@dataclass(slots=True, frozen=True)
class Car(BaseEntity):
    model: str
    year: int

car = Car(id=1, model="Camry", year=2021)

# Оба поля неизменяемы:
# car.id = 2      <- FrozenInstanceError!
# car.model = ""  <- FrozenInstanceError!

```

---

### 3. Подводный камень: Порядок аргументов и значения по умолчанию

При наследовании датаклассов атрибуты конструктора `__init__` собираются по порядку: **сначала поля родителя, затем поля потомка**.

Если у родителя есть поле со значением по умолчанию (default), а у потомка — без него, вы получите синтаксическую ошибку `TypeError`:

```python
@dataclass(frozen=True)
class BaseEntity:
    id: int
    created_at: str = "2026-01-01"  # Поле с дефолтом

@dataclass(frozen=True)
class Car(BaseEntity):
    model: str  # ❌ Ошибка! Обычное поле идет ПОСЛЕ поля с дефолтом

# TypeError: non-default argument 'model' follows default argument

```

#### Решение для Python 3.10+ (`kw_only=True`)

Параметр `kw_only=True` обязывает передавать аргументы по имени и снимает ограничение на порядок полей при наследовании:

```python
@dataclass(slots=True, frozen=True, kw_only=True)
class BaseEntity:
    id: int
    created_at: str = "2026-01-01"

@dataclass(slots=True, frozen=True, kw_only=True)
class Car(BaseEntity):
    model: str  # Работает отлично!

# Инициализация только с явно названными ключами:
car = Car(id=1, model="Camry")

```
