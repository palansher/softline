# Code-First) и стандарте (OpenAPI / Swagger)

У этого нет одного единственного названия, так как речь идет о **концепции (Code-First)** и **стандарте (OpenAPI / Swagger)**, на базе которых работают современные фреймворки.

Главная технология и стандарт, который за этим стоит — **OpenAPI Specification (ранее известная как Swagger)**.

А сам подход, когда документация автоматически создается из вашего кода, называется **Code-First (или Code-Driven) подход к генерации OpenAPI**.

---

## Как это устроено

Вы пишете код API, используете стандартную типизацию языка или специальное декорирование, а фреймворк на лету генерирует:

1. **JSON/YAML-схему** по стандарту OpenAPI.
2. **Интерактивный веб-интерфейс** (чаще всего **Swagger UI** или **ReDoc**), где можно не только читать документацию, но и сразу отправлять тестовые запросы (кнопка *Try it out*).

---

## Самые популярные фреймворки с этой технологией «из коробки»

### 1. FastAPI (Python)

Самый яркий и популярный пример этой технологии. Вы просто описываете типы данных через Pydantic и аннотации Python, а FastAPI автоматически поднимает интерактивную документацию по адресу `/docs` (Swagger) и `/redoc`.

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float

@app.post("/items/")
def create_item(item: Item):
    return item

```

*(Документация с форматом тела запроса и ответов сформируется автоматически).*

### 2. NestJS (TypeScript / Node.js)

В экосистеме Node.js фреймворк NestJS со специальным модулем `@nestjs/swagger` позволяет генерировать OpenAPI-документацию на основе TypeScript-классов и DTO с декораторами (`@ApiProperty()`).

### 3. ASP.NET Core (C# / .NET)

В .NET встроен инструмент **Swashbuckle** (или **NSwag**). Вы создаете обычные контроллеры C# со строгой типизацией, а фреймворк сам отдает Swagger-страницу.

### 4. Spring Boot (Java / Kotlin)

Использует библиотеку **Springdoc-openapi** (или Swagger/Springfox), которая анализирует Java-коды, сигнатуры методов и аннотации для сборки UI-документации.

## Альтернативы в других видах API

Если речь идет не про классический REST API:

* **GraphQL** — имеет встроенную концепцию самодокументируемости (Introspection). На основе вашей схемы данных такие инструменты, как *GraphiQL* или *Apollo Sandbox*, автоматически строят интерактивную документацию.
* **gRPC** — вы описываете контракты в `.proto`-файлах, из которых специальными утилитами (например, `protoc-gen-doc`) генерируется и код приложения, и HTML/Markdown-документация.
