# Памятка по конкурентности, многопоточности и асинхронности в Python

Эта памятка предназначена для специалистов с опытом в DevOps и разработке (включая бэкграунд в PHP), которые хотят системно разобраться, как Python управляет ресурсами процессора, выполнением задач и ввода-вывода (I/O).

---

## 1. Фундаментальные понятия: Базовый словарь

Прежде чем писать код, важно разделить ключевые термины, которые часто ошибочно используют как синонимы.

### Конкурентность vs Параллелизм

* **Конкурентность (Concurrency / Пересечение во времени):**
Архитектурное свойство программы, когда несколько задач **продвигаются вперед одновременно**, переключая внимание ядра процессора с одной на другую.

> *Аналогия:* Один повар режет лук, останавливается, помешивает суп, снова режет лук. Повар один, но делает несколько дел «одновременно».

* **Параллелизм (Parallelism / Физическое совпадение):**
Физическое выполнение нескольких инструкций **в один и тот же момент времени** на разных ядрах процессора или разных процессорах.

> *Аналогия:* Два повара стоят рядом: один режет лук, второй в эту же секунду помешивает суп.

```
Конкурентность (1 ядро CPU):  [Task1][Task2][Task1][Task2] ──► Время
Параллелизм   (2 ядра CPU):  [Task1][Task1][Task1] ────────► Ядро 1
                             [Task2][Task2][Task2] ────────► Ядро 2

```

### Типы нагрузок: I/O-Bound vs CPU-Bound

1. **I/O-Bound (Нагрузка на ввод-вывод):**
Программа большую часть времени **ждет ответа от внешних устройств или сети**: диск, сетевые HTTP-запросы, ответы от БД, системные вызовы (например, `ping`).
*Примеры в DevOps:* Сбор метрик с 500 серверов, парсинг логов с диска, вызовы Kubernetes API.
2. **CPU-Bound (Нагрузка на процессор):**
Программа загружает процессор математическими или логическими вычислениями на 100%.
*Примеры в DevOps:* Шифрование/расшифровка секретов, парсинг гигантских JSON/YAML в память, сжатие архивов, подсчет хешей.

### Модели многозадачности

* **Вытесняющая многозадачность (Preemptive Multitasking):**
Операционная система сама решает, когда прервать поток/процесс и отдать квант времени процессора другому. Программа не управляет этим процессом. (Используется в `threading` и `multiprocessing`).
* **Кооперативная многозадачность (Cooperative Multitasking):**
Программа (или её рантайм) сама решает, когда уступить управление. Переключение происходит строго в заранее определенных разработчиком точках. (Используется в `asyncio` через `await` и в генераторах через `yield`).

## 2. Мост из мира PHP в Python

Для специалиста, пришедшего из PHP, модель Python может показаться непривычной из-за разницы в жизненном цикле процессов:

```
+-----------------------------------------------------------------------+
|  PHP (Классический PHP-FPM)                                           |
|  - Shared-nothing архитектура: каждый запрос обрабатывается           |
|    изолированным воркером (процессом).                                |
|  - Память очищается полностью после завершения запроса.              |
|  - Конкурентность масштабируется добавлением FPM-воркеров в OS.       |
+-----------------------------------------------------------------------+
                                   │
                                   ▼
+-----------------------------------------------------------------------+
|  Python (Asyncio / Long-running processes)                            |
|  - Один долгоживущий процесс может держать thousands соединений.      |
|  - Память и глобальные переменные сохраняются между запросами.        |
|  - Для I/O использует Event Loop внутри ОДНОГО процесса/потока.        |
|  (Аналог в PHP: Swoole, Workerman, Amp, ReactPHP).                    |
+-----------------------------------------------------------------------+

```

## 3. Подходы к реализации в Python и их сравнение

В Python существует 4 основных способа выполнения кода:

### 1. Синхронный код (Baseline)

Выполнение идет строго последовательно, строка за строкой. Если шаг 2 ждет ответа от сети 5 секунд, вся программа стоит 5 секунд.

### 2. Многопоточность (`threading` / `concurrent.futures.ThreadPoolExecutor`)

Операционная система создает несколько потоков внутри **одного процесса**. Потоки делят общее пространство памяти.

### 3. Многопроцессность (`multiprocessing` / `concurrent.futures.ProcessPoolExecutor`)

Создаются изолированные процессы Python (каждый со своим интерпретатором и своей памятью).

### 4. Асинхронность (`asyncio`)

Один поток, один процесс. Внутри работает **Event Loop (событийный цикл)**, который переключает выполнения корутин в моментах ожидания I/O (обозначенных ключевым словом `await`).

---

## 4. Главное ограничение CPython: GIL (Global Interpreter Lock)

Нельзя изучать конкурентность в Python, не зная про **GIL**.

> **GIL (Глобальная блокировка интерпретатора)** — это внутренний механизм CPython (эталонной реализации Python), который разрешает выполнять байт-код Python только **одному потоку в один момент времени**, даже если на сервере 128 ядер CPU.

### Как GIL влияет на практику

* **Для CPU-Bound задач:** Многопоточность (`threading`) **БЕСПОЛЕЗНА** и даже вредна. 4 потока на 4 ядрах будут выполняться по очереди на одном ядре из-за GIL, а время потратится на контекстные переключения.
* **Для I/O-Bound задач:** GIL **НЕ МЕШАЕТ**. Когда поток делает системный вызов на ожидание сети или файла (например, `socket.read()`), CPython **освобождает GIL**, позволяя другим потокам работать.

## 5. Разбор распространенных мифов

> ❌ **Миф 1: «Асинхронность (asyncio) делает вычисления быстрее».**
> **Реальность:** `asyncio` не ускоряет работу процессора. Если вы запустите математический расчет внутри `async def`, он выполнится с той же скоростью (или чуть медленнее), что и в обычной функции, заблокировав весь Event Loop.

> ❌ **Миф 2: «Потоки в Python работают параллельно на всех ядрах».**
> **Реальность:** Из-за GIL потоки Python выполняются конкурентно, но НЕ параллельно (если речь идет о коде на Python). Настоящий параллелизм дают только процессы (`multiprocessing`).

> ❌ **Миф 3: «Использование yield или генераторов ускоряет чтение файлов по сравнению с циклом».**
> **Реальность:** И обычный `for line in file:`, и генератор с `yield` читают файл построчно с одинаковой эффективностью памяти $O(1)$. `yield` нужен для архитектуры и создания цепочек обработки данных (пайплайнов).

## 6. Матрица выбора подходов (Чек-лист для DevOps)

| Тип задачи | Рекомендуемый подход | Почему именно он | Что использовать в Python |
| --- | --- | --- | --- |
| **I/O-Bound (тысячи соединений)** | **`asyncio`** | Высочайшая масштабируемость, единицы МБ RAM на 10k соединений. | `async def`, `aiohttp`, `httpx` |
| **I/O-Bound (десятки/сотни скриптов/запросов)** | **`ThreadPoolExecutor`** | Простая интеграция в старый синхронный код без переписывания на `async`. | `concurrent.futures` |
| **CPU-Bound (вычисления, парсинг)** | **`ProcessPoolExecutor`** | Полный обход GIL, задействование всех ядер CPU. | `multiprocessing` |
| **Системные команды OS (ping, ssh)** | **`asyncio.subprocess`** | Легкое управление фоновыми процессами ОС без блокировки. | `asyncio.create_subprocess_exec` |

## 7. Практические примеры кода

Рассмотрим реализацию задачи: **проверить список сайтов на доступность**.

### Вариант А: Многопоточность (`ThreadPoolExecutor`)

*Идеально, когда нужно быстро параллелить старый синхронный код.*

```python
from concurrent.futures import ThreadPoolExecutor
import requests

urls = ["https://mail.ru", "https://yandex.ru", "https://vk.com"]


def check_url(url):
    # Синхронный блокирующий запрос
    response = requests.get(url, timeout=3)
    return f"{url}: {response.status_code}"


# Создаем пул из 3 потоков
with ThreadPoolExecutor(max_workers=3) as executor:
    # map автоматически распределяет элементы списка по потокам
    results = executor.map(check_url, urls)

for res in results:
    print(res)

```

### Вариант Б: Многопроцессность (`ProcessPoolExecutor`)

*Используется, если вместо легкого HTTP-запроса выполняется тяжелая обработка (например, сжатие изображений или парсинг тяжелого лог-файла).*

```python
from concurrent.futures import ProcessPoolExecutor
import hashlib


def heavy_hash_computation(data):
    # CPU-bound операция: тяжелый подсчет хешей
    result = data
    for _ in range(1_000_000):
        result = hashlib.sha256(result.encode()).hexdigest()
    return result


if __name__ == "__main__":
    # Обязательное условие для multiprocessing в Python — защищенная точка входа
    items = ["payload1", "payload2", "payload3"]

    # Каждый воркер — это отдельный процесс ОС со своим GIL
    with ProcessPoolExecutor(max_workers=3) as executor:
        results = executor.map(heavy_hash_computation, items)

    for res in results:
        print(res[:10])

```

### Вариант В: Асинхронность (`asyncio` + `httpx`)

*Идеальный выбор для высокого I/O с контролем состояния каждой корутины.*

```python
import asyncio
import httpx

urls = ["https://mail.ru", "https://yandex.ru", "https://vk.com"]


async def check_url_async(client, url):
    # Неблокирующий асинхронный HTTP-запрос
    response = await client.get(url, timeout=3)
    return f"{url}: {response.status_code}"


async def main():
    # Создаем единую асинхронную сессию
    async with httpx.AsyncClient() as client:
        # Формируем список корутин
        tasks = [check_url_async(client, url) for url in urls]

        # Запускаем все запросы одновременно в Event Loop
        results = await asyncio.gather(*tasks)

        for res in results:
            print(res)


asyncio.run(main())

```

## 8. Ограничения и подводные камни ("Чудес не бывает")

1. **Блокировка Event Loop в asyncio:**
Если внутри корутины (`async def`) вызвать обычную блокирующую функцию (например, `time.sleep(5)` или `requests.get()`), **весь Event Loop замирает**. Ни одна другая корутина не выполнится, пока блокирующий вызов не завершится.

* *Решение:* Используйте асинхронные аналоги (`asyncio.sleep()`, `httpx`, `aiofiles`) или уносите блокирующий код в отдельный поток через `asyncio.to_thread()`.

1. **Оверхед по памяти у процессов:**
Каждый процесс Python (`multiprocessing`) съедает от 10-30 МБ RAM просто на запуск интерпретатора. Создание 1000 процессов обрушит систему по OOM (Out Of Memory), тогда как 1000 корутин в `asyncio` займут всего пару мегабайт.
2. **Сложность отладки (Debugging & Tracing):**
Трейсбэки ошибок в асинхронном коде из-за переключения контекстов Event Loop могут быть нелинейными и сложными для чтения по сравнению со стандартным синхронным стеком.
