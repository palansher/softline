## 1. Что такое `async def`?

Обычная функция `def` при вызове сразу начинает выполнять свой код и возвращает значение.

`async def` объявляет **функцию-корутину**.

1. Когда вы вызываете такую функцию (например, `async_ping("mail.ru")`), её код **НЕ начинает выполняться сразу**.
2. Вместо этого Python создаёт и возвращает специальный **объект-корутину** (по сути, «заготовку» для задачи).
3. Чтобы код внутри действительно начался, эту корутину нужно **передать в Event Loop** (например, через `await`, `asyncio.create_task()` или `asyncio.gather()`).

---

## 2. Что делает звёздочка `*` в `*tasks` и `*command`?

Звёздочка `*` перед списком или кортежем — это **оператор распаковки (Unpacking Operator)**. Он берет элементы из массива и передает их в функцию не как единый список, а как **отдельные аргументы через запятую**.

Представьте разницу:

- **Без звездочки:** `print([1, 2, 3])` $\rightarrow$ Функция получает **1 аргумент** (список целиком) и печатает `[1, 2, 3]`.
- **Со звездочкой:** `print(*[1, 2, 3])` $\rightarrow$ Эквивалентно `print(1, 2, 3)`. Функция получает **3 отдельных аргумента** и печатает `1 2 3`.

### Зачем это в вашем коде?

1. **`asyncio.gather(*tasks)`**: Функция `asyncio.gather` устроена так, что она принимает задачи **через запятую**: `gather(task1, task2, task3)`. Если передать в нее список без звездочки `gather(tasks)`, она попытается распарсить сам список как одну задачу и выдаст ошибку. Звездочка `*tasks` распаковывает список из 5 корутин в 5 отдельных аргументов.
2. **`*command`**: Функция `create_subprocess_exec` ждет аргументы в виде: `("ping", "-c", "1", "mail.ru")`. Звездочка `*command` превращает массив `["ping", "-c", "1", "mail.ru"]` в набор этих отдельных строк.

## 📋 Заметка: Обзор и особенности скрипта

### Что делает скрипт

Скрипт проверяет сетевую доступность нескольких узлов (IP-адресов и доменов), вызывая системную утилиту `ping` для каждого хоста. Вместо того чтобы проверять их по очереди (один за другим), программа пингует **все хосты одновременно**.

---

### Главные особенности реализации

1. **Параллелизм без многопоточности (Non-blocking Subprocesses)**

- Скрипт не использует классические `threading` или `multiprocessing`.
- Вместо этого метод `asyncio.create_subprocess_exec` делегирует выполнение команды `ping` самой операционной системе. Пока ОС ждет ответа от сервера `mail.ru`, Python в том же самом потоке моментально отправляет следующий запрос к `yandex.ru`.

1. **Кроссплатформенность (Cross-platform flexibility)**

- Команда `ping` отличается в разных операционных системах:
- В **Windows** параметр количества пакетов задается через `-n 1`.
- В **Linux / macOS** тот же параметр задается через `-c 1`.

- Скрипт автоматически определяет текущую ОС через `platform.system()` и подставляет нужный флаг.

1. **Изоляция вывода (Pipes)**

- `stdout=asyncio.subprocess.PIPE` перехватывает текстовый вывод команды `ping`. Это позволяет «скрыть» сырой технический текст команды `ping` от пользователя и выдать лаконичное сообщение: `mail.ru доступен!`.

1. **Группировка задач через `asyncio.gather**`

- Все 5 проверок запускаются одновременно.
- Общее время работы скрипта равно времени **самого долгого** одиночного пинга (обычно 1–2 секунды для несуществующего домена), а не сумме всех пингов.

Всё дело в том, что метод `communicate()` возвращает **кортеж (tuple) из двух элементов**, а Python использует механизм **распаковки кортежей (Tuple Unpacking)**.

## Как вывод метода communicate попадает в две разных переменных (stdout, stderr )

### 1. Что именно возвращает метод `communicate()`?

Когда асинхронная операция `await process.communicate()` завершается, она отдаёт единую структуру данных — кортеж из двух байтовых строк:

```python
(b"Ответ от 8.8.8.8: число байт=32...", b"")  # (stdout_data, stderr_data)

```

1. **Первый элемент кортежа** — всё, что программа напечатала в стандартный поток вывода (`stdout`).
2. **Второй элемент кортежа** — всё, что программа отправила в поток ошибок (`stderr`).

---

### 2. Как работает распаковка в Python

В Python можно присваивать элементы кортежа нескольким переменным одновременно в одну строчку.

Посмотрим на простой пример без асинхронности:

```python
# Создаем кортеж из двух элементов
my_tuple = ("Данные из stdout", "Ошибок нет")

# Распаковываем кортеж в две переменные
stdout, stderr = my_tuple

print(stdout)  # Выведет: Данные из stdout
print(stderr)  # Выведет: Ошибок нет

```

Если количество переменных слева от знака `=` совпадает с количеством элементов в кортеже справа, Python автоматически распределяет их по порядку:

- Первую переменную (`stdout`) связывает с первым элементом `[0]`.
- Вторую переменную (`stderr`) связывает со вторым элементом `[1]`.

---

### 3. Пошаговая цепочка в вашем коде

Когда вы пишете:

```python
stdout, stderr = await process.communicate()

```

Происходит 3 последовательных шага:

```text
1. Выполнение:
   await process.communicate() 
        │
        ▼
2. Получение результата (кортеж из двух элементов):
   (b"Reply from 8.8.8.8...", b"")
        │
        ▼
3. Распаковка Python'ом:
   stdout  <──  b"Reply from 8.8.8.8..."  (элемент [0])
   stderr  <──  b""                     (элемент [1])

```

---

### 💡 Важная деталь: Тип данных `bytes`

Обратите внимание, что `communicate()` возвращает данные в виде **байтовых строк** (`bytes`), а не обычного текста (`str`).

В консоли они выглядят со специальным префиксом `b'...'`:

```python
print(type(stdout))  # <class 'bytes'>
print(stdout)  # b'Pinging mail.ru [217.69.139.229] with 32 bytes of data:\r\n...'

```

Чтобы превратить их в обычный читаемый текст (строку), их нужно раскодировать методом `.decode()`:

```python
# Для Windows чаще используется кодировка 'cp866' или 'utf-8' (в зависиомсти от настроек консоли)
text_output = stdout.decode("cp866")
print(text_output)

```

## Главная дилемма: Почему используют утилиту `ping`?

запуск отдельного системного процесса через `create_subprocess_exec` на каждый хост — это действительно **тяжелая операция** (создание процесса в ОС требует ресурсов CPU и RAM на выделение памяти, таблицы дескрипторов и т.д.).

Однако в мире сетей есть важное разграничение между **ICMP (Layer 3)** и **TCP (Layer 4)**.

Утилита `ping` использует протокол **ICMP (Internet Control Message Protocol)**.

Чтобы отправить чистый ICMP-пакет напрямую из Python (без вызова внешних программ), нужно открыть так называемый **Raw Socket (сырой сокет)**:

```python
import socket
# Требует прав root / sudo / Administrator!
s = socket.socket(socket.AF_INET, socket.SOCK_RAW, socket.IPPROTO_ICMP)

```

⚠️ **Проблема:** В 99% операционных систем создание сырых сокетов разрешено **только пользователю `root` (или Administrator в Windows)**.

Утилита `ping` в Linux имеет специальный флаг безопасности (`SUID` или `CAP_NET_RAW`), который позволяет обычным пользователям отправлять ICMP-пакеты. Поэтому в учебных примерах часто вызывают системный `ping` — это простой способ сделать ICMP-проверку без прав суперпользователя.

---

### Нативный и легкий способ: Проверка через TCP-сокеты

Если вам не принципиален именно протокол ICMP, а нужно просто понять, **жива ли машина и отвечает ли она по сети**, в Python есть встроенный, крайне легковесный способ — **попытка открыть TCP-соединение** (например, на порт `80` (HTTP), `443` (HTTPS) или `22` (SSH)).

Это делается **нативно внутри Event Loop** с помощью `asyncio.open_connection()`. Никаких сторонних процессов и никаких прав `root`!

#### Пример асинхронной проверки через TCP-сокет:

```python
import asyncio


async def async_check_port(host, port=80, timeout=2.0):
    try:
        # Нативный неблокирующий вызов системного сокета из Python
        reader, writer = await asyncio.wait_for(
            asyncio.open_connection(host, port), timeout=timeout
        )

        # Если соединение установилось — хост точно доступен!
        writer.close()
        await writer.wait_closed()
        return f"{host}:{port} доступен!"

    except (asyncio.TimeoutError, OSError):
        # TimeoutError — хост не ответил за timeout секунд
        # OSError — хост сбросил соединение (RST) или сработал файрвол
        return f"{host}:{port} не доступен!"


async def main():
    hosts = ["mail.ru", "yandex.ru", "8.8.8.8", "192.168.1.254"]

    # Проверяем порт 443 (HTTPS) на всех хостах одновременно
    tasks = [async_check_port(host, port=443) for host in hosts]
    results = await asyncio.gather(*tasks)

    for result in results:
        print(result)


asyncio.run(main())

```

### Сравнение подходов

| Характеристика | Вызов системного `ping` | Нативный `asyncio.open_connection` |
| --- | --- | --- |
| **Уровень OSI** | Layer 3 (Network / ICMP) | Layer 4 (Transport / TCP) |
| **Оверхед на хост** | 🔴 **Высокий** (создание процесса ОС) | 🟢 **Минимальный** (пара килобайт RAM) |
| **Права доступа** | Обычный пользователь | Обычный пользователь |
| **Скорость (1000 хостов)** | Медленно (лимит на процессы ОС) | ⚡ Моментально (десятки тысяч сокетов) |
| **Условие работы** | Хост должен отвечать на ICMP Echo | На хосте должен быть открыт хотя бы один порт |

---

### Итог для DevOps

1. Если нужно сделать **быстрый и легкий сканер доступности** (например, для мониторинга веб-серверов или баз данных), всегда используйте **TCP-сокеты (`asyncio.open_connection`)**. Это работает в тысячи раз быстрее и потребляет минимум ресурсов.
2. Вызов системной утилиты `ping` через `create_subprocess_exec` имеет смысл только тогда, когда вам критически важно проверить узел именно по протоколу ICMP, а прав `root` в контейнере/системе у вашего Python-скрипта нет.
