CLI во Flask — это удобнейший инструмент, и в контейнерах им пользуются постоянно.

Внутри контейнера Flask-CLI используется для **административных задач**, **миграций БД**, **создания суперпользователей** или **запуска фоновых скриптов**, не создавая для этого отдельный HTTP-эндпоинт.

---

## Как это работает?

Когда ты пишешь код на Flask, ты можешь регистрировать свои собственные команды с помощью декоратора `@app.cli.command()`.

### 1. Пример кода в `app.py`

```python
from flask import Flask

app = Flask(__name__)

# Простая custom-команда
@app.cli.command("init-db")
def init_db():
    """Инициализация базы данных."""
    # Тут может быть логика: db.create_all() или запуск первичных фикстур
    print("База данных успешно инициализирована!")

@app.cli.command("create-admin")
def create_admin():
    """Создать администратора."""
    print("Администратор admin@example.com создан!")

```

## Как запускать команды внутри контейнера?

Есть два основных способа выполнять CLI-команды Flask в Docker:

### Способ 1. Выполнение в уже запущенном контейнере (`docker exec`)

Это самый частый сценарий. Контейнер `service2image-prod` работает в фоновом режиме, а ты «снаружи» просишь его выполнить CLI-команду:

```bash
docker exec -it service2image-prod flask init-db

```

Или для создания админа:

```bash
docker exec -it service2image-prod flask create-admin

```

> 💡 **Как Flask понимает, откуда брать приложение?**
> Если главный файл называется `app.py` или `wsgi.py`, утилита `flask` находить его **автоматически**. Если файл называется иначе (например, `main.py`), нужно передать переменную окружения:
> `docker exec -it -e FLASK_APP=main.py service2image-prod flask init-db`

---

### Способ 2. Автоматический запуск при старте (в `compose.prod.yaml` / Entrypoint)

Часто перед тем как запустить сам Gunicorn, нужно применить миграции базы данных (Alembic / Flask-Migrate). Это делают прямо перед стартом веб-сервера.

В `compose.prod.yaml` это выглядит так:

```yaml
services:
  service2image:
    image: service2image-prod
    container_name: service2image-prod
    # Сначала накатываем миграции через CLI Flask, затем запускаем Gunicorn
    command: >
      sh -c "flask db upgrade && 
             gunicorn --bind 0.0.0.0:5002 --workers 4 --threads 2 app:app"

```

## Встроенные команды Flask, о которых стоит знать

Даже без написания своего кода у Flask «из коробки» есть полезные CLI-команды:

| Команда | Что делает |
| --- | --- |
| `flask routes` | Показывает **все зарегистрированные URL-маршруты** (routes), методы (GET/POST) и привязанные функции. Очень удобно для отладки! |
| `flask shell` | Запускает интерактивный Python REPL с автоматически импортированным контекстом приложения (`app`, `db` и т.д.). |

Попробуй прямо сейчас выполнить в своем терминале:

```bash
docker exec -it service2image-prod flask routes

```

И Flask выведет красивую таблицу всех эндпоинтов твоей системы!
