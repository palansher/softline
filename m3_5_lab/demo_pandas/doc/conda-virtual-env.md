# Виртуальное окружение Сonda

## 1. Как выключить (деактивировать) окружение

Эта команда возвращает вас в базовое окружение (base) или в системную среду. При этом указывать имя окружения не нужно.

`conda deactivate`

## 2. Как удалить окружение

Перед удалением окружения его обязательно нужно сначала деактивировать.

После деактивации выполните команду удаления. Замените my_env на имя вашего окружения (например, то, где вы ставили pandas):

`conda remove --name my_env --all`

ключ `--all` означает полное уничтожение всего окружения.

- Без ключа --all: Conda потребует указать конкретное имя пакета, который нужно удалить из окружения (например, conda remove --name my_env pandas).
- С ключом --all: Conda понимает, что не нужно удалять пакеты по одному. Она полностью стирает саму папку окружения my_env, удаляя из неё абсолютно все установленные библиотеки, Python и сопутствующие файлы метаданных.

## Полезные команды для проверки

- Посмотреть список всех окружений: если вы забыли точное имя, проверьте его этой командой (активное окружение будет отмечено звездочкой *):

`conda env list`

или

`conda info --envs`

- Удаление без подтверждения: чтобы Conda не спрашивала вас Proceed ([y]/n)?, добавьте флаг -y:

`conda remove --name my_env --all -y`

## Как очистить кэш Conda

Чтобы полностью очистить кэш Conda и освободить место на жестком диске после удаления окружений, используйте команду `conda clean`.

- Удалить неиспользуемые пакеты и кэш тарболов: эта команда удалит все скачанные установочные файлы (.tar.bz2 или .conda) и старые пакеты, которые больше нигде не используются.

conda clean --all

- Удалить только скачанные архивы пакетов: если вы хотите стереть только загруженные из интернета файлы установщиков, но оставить кэш индексов.

conda clean --tarballs

- Удалить неиспользуемые скопированные пакеты: удаляет кэш распакованных пакетов, которые не привязаны ни к одному из текущих окружений.

conda clean --packages

### Важные нюансы

- Флаг подтверждения: как и при удалении окружения, вы можете добавить в конец ключ -y (например, conda clean --all -y), чтобы очистка прошла автоматически без запроса подтверждения.
- Безопасность: команда conda clean --all полностью безопасна — она никогда не затронет пакеты, которые в данный момент используются в ваших активных окружениях.

Хотите узнать, как проверить, сколько места занимают окружения Conda на вашем диске?

## Сколько места занимает Conda

Чтобы узнать, сколько дискового пространства занимают ваши окружения и кэш пакетов, выполните команду:

`conda info`

В выводе этой команды обратите внимание на две строки:

- package cache: путь к папке, где хранятся скачанные пакеты (именно её очищает conda clean).
- envs directories: пути к папкам, где установлены сами виртуальные окружения. [1, 2]

Размер этих папок на диске покажет, сколько гигабайт памяти освободилось или можно освободить.

### Как узнать размер каждого неактивного окружения?

Сама Conda не умеет показывать точный вес окружений в гигабайтах, но зная пути к папкам из команды выше, это легко сделать с помощью стандартных утилит Linux.

Поскольку в вашем conda info указано, что окружения по умолчанию создаются в папке /home/vp/miniconda3/envs, вы можете узнать размер каждого из них, выполнив в терминале команду

 `du -sh /home/vp/miniconda3/envs/*`

Если у вас также создавались окружения во втором пути (/home/vp/.conda/envs), проверьте их аналогично:

`du -sh /home/vp/.conda/envs/*`

## Создать чистое Python-окружение

Создать чистое Python-окружение со всеми библиотеками одной командой можно через Conda, UV или стандартный venv.

### 🛠️ Через Conda (для Data Science)

Идеально подходит для работы с тяжелыми зависимостями.

- Команда: `conda create -n имя_окружения python=3.10 numpy pandas -y`
- Имя: --n задает название проекта.
- Версия: python=3.10 скачает нужный интерпретатор.
- Библиотеки: numpy pandas установятся автоматически.
- Автоматизация: -y пропустит подтверждение установки.

### ⚡ Через UV (самый быстрый метод)

Современный менеджер на Rust, который создает окружение за доли секунды.

- Команда: `uv venv --python 3.11 имя_окружения`
- Скорость: Работает в 3–5 раз быстрее pip.
- Установка библиотек: uv pip install numpy pandas внутри окружения.

### 📦 Через Встроенный venv (без стороннего софта)

Использует стандартные инструменты Python, объединенные через оператор &&.

- Команда: `python3.10 -m venv myenv && source myenv/bin/activate && pip install numpy`
- Создание: python3.10 -m venv создает папку.
- Активация: source myenv/bin/activate включает его.
- Установка: pip install накатывает нужные пакеты. [3, 7, 8, 9]

## 🔄 Характер взаимоотношений окружений в Conda

```
conda env list

# conda environments:
#
# * -> active
# + -> frozen
base                 *   /home/vp/miniconda3
data_env                 /home/vp/miniconda3/envs/data_env
lab35                    /home/vp/miniconda3/envs/lab35
```

Вопреки визуальному расположению папок в структуре /home/vp/miniconda3/envs/, окружения Conda не являются иерархическими (вложенными).

Окружение base и созданные вами data_env или lab35 находятся в отношениях полной изоляции и равноправия.

- Полная изоляция (Независимость):

Пакеты, установленные в base (например, определенная версия pandas или numpy), абсолютно не видны внутри data_env или lab35.

Каждое окружение имеет свой собственный независимый набор библиотек и даже может иметь совершенно разные версии самого Python.

- Отсутствие наследования:

Если вы обновите библиотеку в base, в остальных окружениях ничего не изменится.

Настройки и переменные окружения у каждого свои.

- Физическое разделение папок:

То, что папка envs/ находится внутри директории miniconda3, — это лишь организационное решение Conda для хранения файлов в одном месте (так называемый центральный репозиторий окружений).

С технической точки зрения Conda просто переключает пути выполнения (переменную PATH) на нужную изолированную папку.

### 🧠 Единственная реальная связь: Кэш пакетов

Единственное, что их по-настоящему объединяет — это общий кэш пакетов (Package Cache) на вашем жестком диске (в вашем случае это папка /home/vp/miniconda3/pkgs).

- Когда вы устанавливаете, например, numpy в окружение data_env, Conda сначала скачивает его в общую папку pkgs.
- Если позже вы решите установить точно такую же версию numpy в окружение lab35, Conda не будет скачивать её заново из интернета. Она просто создаст жесткую ссылку (hard link) из папки pkgs в папку lab35/lib/....
- Это экономит огромное количество места на диске и ускоряет создание новых сред, сохраняя при этом их 100% независимость друг от друга.

создать окружение в совершенно другом месте (вне папки envs/), можно используя флаг --prefix.
